## 0. 一枚まとめ

1. **CAD から機体の設計値が出た。** 取付角は厳密に **±60.0000° / ±135.0000°**、接地点半径 **78.450 mm**、
   車軸は位置ベクトルと完全に反平行、**ローラの傾き 0.0000°**。全機体がこの設計 (2026-09-23 にユーザーが確認)。
2. **車輪だけで取付角の比を決められる閉形式を導いた** (§2.4)。Rojas の対称ロボット用の整合検査
   `v1−v2+v3−v4=0` を前後で角度が違う機体へ拡張すると
   **`n = (r_i/s_i)·(sinθ, −sinφ, sinφ, −sinθ)`** という左零ベクトルになる。
   vision も時刻合わせも要らず、車輪のログだけで判定できる。
3. **【決着】幾何は CAD の 60° が正しく、オドメトリに使うべき「有効角度」は 55〜56°** (§2.5)。
   両立する。ローラのコンプライアンスと滑りで、自由方向の運動の約 9% が車輪回転に漏れるため、
   当てはめると実効的に小さい角度・短いアームとして現れる。文献でいう
   **effective kinematic parameters** がこれで、「幾何を測るのではなく有効ヤコビアンを較正せよ」が定説。
   **フィルタには有効値、CAD は検算と歯止めに使う。**
4. **「どれが正しいか」を選ぶのをやめる部分もある。** 車輪半径のような**倍率**は
   フィルタの状態にしてオンライン較正する (実測: 6% の半径誤りで vision 2 s 欠落の誤差が
   217 → 49.7 mm)。ただし**輪ごとの角度差は低次元の倍率では吸収できない** (§4.1)。
5. **PoC と実機ログが、既定パラメータを 4 つ否定した** (§1, §5.1):
   vision 雑音 5 mm → **0.4 mm**、車輪雑音 0.01 → **0.23 + 0.07·|ω| rad/s**、
   角加速度の雑音 20 → **5.0**、ZUPT の車輪しきい値 0.15 → **0.7 rad/s** (雑音より低く、一度も成立していなかった)。
6. **vision の定数遅延は「原理的に分離不能」ではない。** 車輪という独立した速度源があれば
   相関で決まる (§4.3)。合成データで ±1 ms、実機でも 13〜25 ms を検出した。
7. **スリップは指数減衰の外乱として状態に持つのが正解**で、α > 0 でなければ不可観測
   (Yu ほかの可観測性解析)。実機でも効いた (スリップ状態を切ると位置 RMSE 0.56 → 0.83 mm)。
8. **オムニ車輪の有効転がり半径は一定ではない** (polygon 効果)。**車輪雑音を速度に比例させる**のが
   物理的に正しく、実機で効いた (誤スリップ率 0.31 → 0.046、NEES 3.57 → 2.00)。

## 1. 出発点 — PoC が変えた前提

`localization-handoff.md` は「実機では一度も動かしていない」段階で書かれた。その後 PoC で実測が入り、
**前提が 3 つ変わった**。

| 項目 | 計画・実装時の想定 | PoC の実測 | 影響 |
|---|---|---|---|
| vision の雑音 | 5 mm / 0.5° (プレースホルダ) | **0.2〜0.4 mm / 0.25〜0.32°** | フィルタが vision を過小評価している。R を 100 倍以上絞れる |
| vision のレート | 60 Hz 前後・欠落あり | **約 116 Hz**、最大の途切れ 17〜34 ms | 「欠落耐性」より「遅延補償」が主な価値になる |
| 車輪の雑音 | 0.01 rad/s (量子化基準) | **0.3 rad/s 相当** | 既定では車輪更新の 95% が Huber で潰されていた |
| vision の片道遅延 | 「原理的に分離できない定数が残る」 | timesync の残差 **0〜4 ms**、車輪は 8〜12 ms 古い | §5.2 で「最大の発見」とされた問題は、実は測れている |
| 機体パラメータ | 4 ソースで食い違い・未確定 | 同定済み (55.4°/74 mm/28〜29 mm) | ただし **CAD と食い違う** (§2) |
| 指令が効くまでの遅れ | 未計測 | **約 90 ms、電池電圧で変わる** | `PredictAhead` が必須。しかも固定値にできない |

**要するに、推定器の役割が変わった。**
「雑音をならす・途切れを埋める」装置ではなく、**「遅れを埋め、速度を作り、機体パラメータを較正し続ける」装置**である。
vision が 116 Hz・0.3 mm で来る環境では、平滑化の利得はほとんど無い (handoff §5-11 の結論と一致)。

## 2. 3D モデルから出た機体の設計値

### 2.1 方法

`~/Downloads/Robot_V2.step` (AP214, 199 万エンティティ, 112 MB) を解析した。
`NEXT_ASSEMBLY_USAGE_OCCURRENCE` → `CONTEXT_DEPENDENT_SHAPE_REPRESENTATION` →
`REPRESENTATION_RELATIONSHIP_WITH_TRANSFORMATION` → `ITEM_DEFINED_TRANSFORMATION` の連鎖をたどって
組立ツリーの各部品のワールド変換を求め、`WheelUnit_V1_4` × 4 とその下の `OmniWheel` / `Omni_V1_4` /
`SIdeWheel_Bambi` × 30 の配置と B-rep 形状を robot 座標へ写した。

- **ロボット座標の決め方**: `Dribbler_V3` が CAD の `y = −77.4 mm` にあるので **前方 = −y_cad**。
  右手系を保つと `(x_r, y_r) = (−y_cad, x_cad)`。
- **接地点**: 車軸は `z = 24.75 mm`、ハブ板は外径 26.705 mm・幅 12 mm、
  ローラのピッチ円は軸から 25.000 mm。CAD の `z = 0` は接地面ではなく底板基準
  (ハブの最下点が `z = −1.88 mm` に来るため)。

### 2.4 【新規】車輪だけで取付角の比が決まる — 冗長性の閉形式

Rojas は対称オムニ (全輪同じ角 φ) の整合検査が `(I − DD⁺)m = 0` ⟺ `v1 − v2 + v3 − v4 = 0` になり、
**φ に依存しない**ことを示した。本機は前 φ、後 θ で角度が違うので、この結果はそのまま使えない。

速度結合行列の行を本リポジトリの基準形

```
omega_i = (s_i / r_i) · ( sin(α_i)·vx − cos(α_i)·vy − R·ω )
```

とし、角度を `α = (φ, θ, −θ, −φ)` とすると、**左零ベクトルは閉形式で書ける**:

```
n_i = (r_i / s_i) · m_i ,     m = ( sinθ, −sinφ, +sinφ, −sinθ )
```

検算 (`Σ m_i = 0`、`Σ m_i sin α_i = 0`、`Σ m_i cos α_i = 0` の 3 本が恒等的に成立する):

```
Σ m_i          = sinθ − sinφ + sinφ − sinθ = 0
Σ m_i sin α_i  = sinθ·sinφ − sinφ·sinθ − sinφ·sinθ + sinθ·sinφ = 0
Σ m_i cos α_i  = sinθ·cosφ − sinφ·cosθ + sinφ·cosθ − sinθ·cosφ = 0
```

φ = θ を入れると Rojas の `(1, −1, 1, −1)` に戻る。**この残差 `nᵀw` には次の性質がある。**

- **スリップが無ければ、どんな運動に対しても厳密にゼロ**。速度推定も vision も時刻合わせも要らない。
- **`R` (モーメントアーム) に依存しない。** 角度と半径の比だけで決まる。
- 55° 説と 60° 説で **`|n_1|` が 0.863 対 0.816 (5.8% 差)**。車輪速が 14 rad/s まで出る本機なら
  この差は 0.6 rad/s 相当の残差になり、量子化 (0.0029 rad/s) の 200 倍。**車輪のログだけで判定できる。**

**使い道は 3 つ。**

1. **vision なしの幾何較正** — `Σ (nᵀw)²` を最小化して `sinθ/sinφ` と半径比を決める。
   遅延・時刻同期・vision の微分雑音が一切入らないので、PoC の同定 (vision 基準、条件数 14) より条件が良い。
2. **スリップ検出** — 残差の正規化二乗を χ²(1) で検定する (Yu らのスリップ事象検出と同じ構造、次元は 1)。
3. **車輪雑音の実測** — 滑っていない区間の残差の分散が、そのまま `WheelNoise` の実測値になる。
   PoC が「0.01 では 95% が Huber で潰され、0.3 程度が妥当」と経験的に見つけた値を、**測って決められる。**

### 2.5 【決着】幾何は CAD どおり。ただしオドメトリに使う値は別物

**2026-09-23 にユーザーから確認が取れた: `Robot_V2.step` は現行の Rock5A 機体そのもので
(CAD の中で Raspberry Pi 5 になっている部品が実際には Rock5A)、以後すべてこの機体になる。**
旧機体を考慮する必要はない。当初「CAD は別の機械世代だろう」と書いたのは**誤りだった**。

CAD を再確認した結果は厳密そのもので、疑う余地はない:

```
FL +60.0000 deg   BL +135.0000 deg   BR -135.0000 deg   FR -60.0000 deg
接地点半径 78.450 mm (4 輪とも)
車軸 . (-位置ベクトル) = 1.000000000   車軸の傾き 1e-17   ローラの傾き 0.0000 deg
```

では実機のデータが 55〜56° を指すのはなぜか。**幾何とオドメトリのパラメータは別物だから**である。

#### 測り方: フィルタを通さない車輪だけの推測航法

いちばん素直な測り方をした。0.3 秒の窓で**車輪から機体速度を復元して積分するだけ**、
フィルタもスムーザも時刻同期も雑音設定も通さない。基準は vision の変位。
9 本・27 窓 (`TestEffectiveGeometryBeatsCADGeometryOnRealData`):

| 前輪角 φ (後輪 135°、半径は各 φ で較正) | 平均誤差 | 中央値 |
|---:|---:|---:|
| 52° | 9.16 mm | 4.77 mm |
| **55°** | **8.93 mm** | 4.06 mm |
| 56° | 8.95 mm | **3.98 mm** |
| 58° | 9.20 mm | 4.55 mm |
| **60° (CAD の幾何)** | **9.75 mm** | **4.91 mm** |

モーメントアームも同じ向きにずれる。回転のある窓で
「車輪から積んだ向きの変化 / vision の向きの変化」を最小二乗で出すと:

| アーム | 傾き (1.0 が正しい) |
|---:|---:|
| **74.0 mm** | **0.9733** |
| 78.45 mm (CAD) | 0.9181 |

傾きは 1/アーム に比例するので、**有効アームは 72.0 mm**。CAD より 8% 短い。

#### なぜずれるか

オムニ車輪は「駆動方向 = 接線」「自由方向 = ローラの転がる向き = ここでは放射方向」だが、
**自由方向は完全には自由ではない** (ローラの軸受け摩擦、ゴムの変形、ローラを回し始める慣性)。
自由方向の運動の一部が車輪の回転に漏れるので、ある機体運動に対して車輪は幾何の予想ほど回らない。
当てはめると、その差が**実効的に小さい取付角・短いアーム**として現れる。
5° のずれは結合係数 `tan 5° = 0.09`、つまり**自由方向の約 9% が漏れる**ことに相当する。

これはオムニ車輪較正の文献でいう **effective kinematic parameters (EKP)** そのもので、
「車輪半径・取付角・中心からの距離をまとめて補正ヤコビアンへ押し込め」というのが定説である。
**旧世代 STM ファームが ±55° の輪にだけ `cos × 1.05` の経験補正を入れていたのも、
同じ現象への手当てだったと考えられる。**

> **実装上の決定**: `DefaultGeometry()` = 有効値 (フィルタが使う)、
> `CADGeometry()` = 幾何の設計値 (検算と歯止め)。
> `cmd/loc_replay` のテストが**有効値が CAD 値より良いことを実データで固定**してある。
> CAD を読んで既定値を「直す」と、そのテストが落ちる。

### 2.6 何がどの情報で決まるか — 較正の切り分け

12 個のパラメータを一度に当てはめるのは筋が悪い。PoC の vision 基準の同定は条件数 14.3、
残差 1.0〜1.2 rad/s (= 実測の車輪雑音とほぼ同じ) で、**モーメントアームが 49〜71 mm と出た**
(幾何 78.45、有効 72)。決まる量と決まらない量が混ざっている。

分けるとこうなる:

| 量 | 何で決まるか | 道具 |
|---|---|---|
| **符号・ホイール順序** | 指令との突き合わせ、または冗長残差 | `loc_ident`、`FitNullVector` |
| **半径の比 (3 自由度)** | **車輪ログだけ**。vision も時刻合わせも要らない | `RadiiFromNullVector` / `CalibrateRadii` |
| 有効取付角・有効アーム | vision が要る。**幾何を測っても出ない** | 車輪だけの推測航法の掃引 (§2.5) |
| 半径の絶対値 | vision が要る | 同上、またはフィルタの `k_v` |
| 倍率のゆっくりした変化 (電池・摩耗) | オンライン | フィルタの `k_v` / `k_w` |

**半径の比が車輪ログだけで決まる**のは §2.4 の閉形式から出る。左零ベクトル `n` に対し
`g_i := n_i s_i / r_i` と置くと `Σ g_i (sin α_i, −cos α_i, −R) = 0` となり、
**`g` は半径に依らない行列の左零ベクトル**になるので

```
r_i = n_i · s_i / g_i
```

で比が直接出る。実機の 8749 サンプルで測ると **4 輪の有効半径は約 5% 違う**
(28.54 / 27.78 / 27.87 / 29.40 mm、平均を 28.4 mm としたとき)。

> **注意: 零ベクトルは冗長方向しか決めない。** 「車輪 → 機体速度」の向き (行空間) は
> 拘束しないので、**推測航法の精度は零ベクトルを合わせても良くならない。**
> 実際、CAD 角度 + 較正半径は零ベクトルへの一致が 100 倍良い (距離 0.0003 対 0.0398) のに、
> 推測航法は悪い (9.75 対 7.96 mm)。**滑り検出には前者、オドメトリには後者**が要る。

## 3. 既存研究から取るもの

読んだのは全文。SSL の先行例だけでは足りない (SSL の公開文献は機上推定の中身をほとんど書かない) ので、
脚ロボット・車両・VIO・ネットワーク時刻同期・統計の各分野から取った。

### 3.1 SSL の先行例 — 何をやっていて、何を書いていないか

**TIGERs Mannheim (ETDP 2016)** は、基地局が SSL-Vision を直接受けてロボットへ位置を中継し、
**`posDelay` (Q6.2 ms、最大 63.75 ms) を一緒に送って「その位置が何ミリ秒前のものか」を機上に伝える**。
機上の sensor fusion (ジャイロ・加速度計・エンコーダ) がそれを使って現在時刻へ内挿する。
返りの `match feedback` には機上推定の位置と速度が入り、**vision から見えていなくても正確な位置を返せる**と明記している。
TDMA・再送なしの専用無線なので遅延が決定論的で、**時計合わせをしないで済む**構造になっている。
→ **本件との差**: 我々は Wi-Fi マルチキャストを機上で直接受けるので、遅延が確率的になる。`posDelay` 方式は使えず、
時刻同期 (凸包法) が要る。この判断は既に正しく実装されている。

**RoboTeam Twente (ETDP 2020)** は数値が貴重:
Xsens MTi-3 で **ジャイロ σ = 0.0011 rad/s (静止) / 0.037 rad/s (走行中)**、
**加速度計 σ = 0.025 m/s² (静止) / 2.5 m/s² (走行中)**。
走行中の加速度計は 100 倍悪化し「state estimation で頼れる精度ではない」と結論。
移動平均で 0.4 m/s² まで落として使っているが、遅延と引き換えである。
彼らの速度推定の σ は 0.025〜0.08 m/s。
→ **取るもの**: **加速度計を速度予測に入れない**。IMU が載ってもジャイロだけを予測の入力にし、
加速度計は衝突検出 (閾値超過で数十 ms だけ Q を膨らませる) に限る。
RAVEN 側の調査文書の結論と一致し、TIGERs が加速度計を予測に使っているのとは逆だが、
**RTT の実測がある以上こちらを採る**。

### 3.2 不変フィルタ — 部分不変が正しい選択だったことの確認

**Hua, Li, Pei, "PIEKF-VIWO" (arXiv:2303.07668)** は、**回転と速度だけを Lie 群に載せ、位置は
ユークリッドのまま切り離す** (`X_I = (exp(ξθ)R̂, exp(ξθ)v̂ + J_l(ξθ)ξv, p̂ + ξp, …)`)。
理由は、完全な IEKF だと伝播行列が位置・速度の推定値に強く依存し、**雑音パラメータの精度に過敏になる**ため。
彼らの実験は MSCKF ベースの VIWO より **一貫性 (NEES) と精度の両方で上回る**。
もう一点重要なのは、**車輪を「相対姿勢の拘束」ではなく「回転–速度の観測」として入れる**ことで、
車輪の 3D 積分と共分散伝播を回避している (「filter consistency に必須」と明記)。
→ **取るもの**: 現実装 (速度をワールド系で持ち、位置はユークリッド、車輪は速度観測) は**この論文と同じ構造**である。
**変更しない。** 根拠として文献を明記しておく。

### 3.3 スリップ — 外乱オブザーバと、適応 R

**Yu ほか, "Fully Proprioceptive Slip-Velocity-Aware State Estimation" (IROS 2023, arXiv:2209.15140)**:

- スリップ速度を **`u̇ = −αu + R·w_u` の自己回帰過程**として状態に持つ (定数モデルではなく指数減衰)。
  理由は「滑りはエネルギーを散逸するので、定数モデルは現実に合わない」。
  → **現実装の `SlipTau` と同じ**。文献的裏付けが取れた。
- **可観測性解析: スリップは α > 0 なら完全可観測、α = 0 なら不可観測。**
  → **`SlipTau` を無限大 (ランダムウォーク) にしてはいけない**理由が理論的に確定した。
- **観測雑音をスリップ量で膨らませる: `W_y = W_0 · exp(‖u‖)`。**
  スリップが大きいときに車輪観測を自動的に信用しなくなる。
  実験では y 軸だけ悪化しており、著者自身が「適応のさせ方が不適切」と認めている。
  → **取るもの**: 採用するが、**軸ごとに別々ではなく等方に効かせ**、上限クランプを付ける。
- スリップ事象の判定は **状態 `u` の χ² 検定** (イノベーションではない)。閾値は χ²₃ の 80% = 4.642。
  → **本件では §2.4 の冗長残差のほうが直接的** (1 自由度、推定に依存しない)。両方を出して比べる。

### 3.4 モデル不確かさのオンライン推定 — 今回の本命

**Mozzarelli, Cattaneo, Corno, Savaresi (arXiv:2403.13452)** は、状態に
**左右の車輪半径 `R_R, R_L` と IMU のヨーレートバイアス `b`** を入れ、
**絶対位置が来ているときだけ補正し、来ないあいだは予測だけ (= 凍結)** する。
観測行列の最初の 3 列 (位置・姿勢) がゼロになるので可観測性が落ちることを明示的に扱い、

- 「予測値を仮想観測として入れる」方式 → **不可観測な状態の共分散が人工的に収束してしまう**ので却下
- 「複数のサブフィルタに分ける」方式 → 相互相関を扱えないので却下

としている。結果、**130 秒・70 m の完全な位置喪失で、累積誤差 5.3 m → 0.35 m、方位 7° → 2° 未満**。

→ **取るもの**: これが §2.3 の食い違いに対する正解である。**「CAD が正しいか同定が正しいか」を選ばない。**
機体パラメータの倍率を状態にして、vision があるうちに較正し、切れたら凍結する。
**機体ごと・電池ごと・タイヤの摩耗ごとの違いも同時に吸収する。**

### 3.5 遅延 — 定数分は「分離不能」ではない

**Qin & Shen, "Online Temporal Calibration for Monocular Visual-Inertial Systems" (IROS 2018)**:
時刻オフセット `t_d` を**状態として最適化**し、観測側を `z(t_d) = z + t_d · V` とずらす
(`V` は観測量そのものの変化率 = 画像面での特徴点速度)。
**ヤコビアンを状態の速度ではなく「観測された変化率」から作る**のが要点で、これにより
定数遅延の推定が素直に効く。オフラインの Kalibr と同等の精度に、オンラインで到達する。

**Larsen ほか (CDC 1998)** は遅延観測の 4 方式を比較し、著者らの「観測を現在時刻へ外挿する」方式は
**遅延区間に他の観測を融合していない場合にのみ最適**であると明記している。
本件は遅延区間に車輪観測が 10 回以上入るので、**外挿方式は準最適**。

**Lynen ほか, MSF-EKF (IROS 2013)** は状態リングバッファに更新を当てて現在まで再予測する方式で、
31 状態でも 1 操作が数十 µs。**センサごとの遅延をオンラインで推定する**ことも枠に入れている。

→ **取るもの**:
1. **現実装の「バッファ区間の再フィルタ」は最適側であり、正しい** (Larsen の分析がそれを裏づける)。変更しない。
2. **`VisionDelayComp` を定数設定から状態へ昇格させる。** ヤコビアンは Qin & Shen に倣い、
   **vision の連続フレームの差分から作った観測速度**を使う (状態の速度ではなく)。
   `v ≈ 0` で不可観測なので、**加減速・旋回中のみ更新**し、それ以外は凍結する (§3.4 と同じ扱い)。
3. **オフラインの初期値は車輪 × vision の相互相関で出す。** PoC が既にこの方法で
   「車輪を 8〜12 ms 古いとしたとき最も合う」と測っている。これは Mair の相互相関法そのものである。

### 3.6 適応雑音 — 実測できない R をどう決めるか

**Särkkä & Hartikainen (arXiv:1302.0681)**、および原典の Särkkä & Nummenmaa の VB-AKF:
観測雑音 `Σ_k` に逆 Wishart 事前分布を置き、状態と同時に変分ベイズで推定する。
実装は驚くほど軽い — 予測で `ν⁻ = ρ(ν−n−1)+n+1`, `V⁻ = ρV`、更新で数回の固定点反復。
**`ρ ∈ (0,1]` が忘却係数**で、1 なら定常、小さいほど時間変動に追従する。

→ **取るもの**: 計画 §4.4 の「適応 R (上下限クランプ付き)」を、**アドホックなイノベーション整合ではなく
VB-AKF で実装する**。逆 Wishart の事前分布が自然に下限を与えるので、クランプが原理から出る。
116 Hz で `ρ = 0.98` なら時定数は約 0.4 s。
**実装は対角のみ** (vision の x, y, θ)。フィールド中央と端、遮蔽、別カメラへの遷移を自動で吸収する。

### 3.7 オムニ車輪の機構 — 有効半径は一定ではない

Mecanum ホイールの文献 (ローラ 12 個 → **30° 周期で転がり半径が変動する「polygon 効果」**) は、
**接触点がローラ間で移り変わるときに回転半径と接触点の軸方向位置が変わり、
滑りと振動を生んで odometry と追従制御の精度を落とす**ことを実験的に示している。

本機は §2.2 の通り **15 個 × 2 列・角ピッチ 12°** なので、

- 転がり半径のリップル周期は **車輪 12° 回転ごと**
- 接触点は 2 列のあいだを **±1 mm** 往復する (千鳥配置のため)
- 0.4 m/s・半径 28 mm では車輪が 14.3 rad/s = 819 °/s なので **約 68 Hz**

→ **取るもの**: **車輪の観測雑音を速度に比例させる**。
`σ_wheel² = σ0² + (k·|ω_wheel|)²`。σ0 は量子化 (0.01/√12 = 0.0029 rad/s) と静止時のノイズ、
`k` が polygon 効果・ローラの弾性・STM の速度制御リップルをまとめて表す。
PoC の「0.3 rad/s 程度が妥当」は走行中の値なので、**`k ≈ 0.3/14.3 ≈ 0.02` が出発点**になる。
これは 125 Hz のサンプリングでは折り返すので、白色雑音として扱ってよい。

## 4. 設計判断 — 実装を何に変えるか

「変えない」ものも根拠つきで残す。handoff §7 の約束 (ビルドタグを付けない・`time.Now()` を呼ばない・
ホットパスでアロケートしない・合成データに合わせ込まない) はすべて維持する。

### 4.1 機体パラメータの倍率を状態にする — ただし万能ではない

**状態を 3 つ増やす**: `k_v` (並進スケール)、`k_w` (回転スケール)、`k_a` (取付角の共通補正)。
車輪の観測モデルを

```
omega_i = (s_i/r_i) · [ sin(α_i + k_a)·u_x − cos(α_i + k_a)·u_y − R·k_w·ω ],
   ただし u = k_v · (v_body + slip)
```

とし、**vision が来ているときだけ更新、来ないあいだは予測のみ (凍結)** とする (Mozzarelli)。
仮想観測も、サブフィルタ分割も使わない。
凍結はゲインの該当行をゼロにして行う。Joseph 形式 `P = (I−KH)P(I−KH)ᵀ + KRKᵀ` は
**任意の K に対して正しい**ので、共分散は整合したままになる (Schmidt-Kalman と同じ扱い)。

**実装後に測って分かった、この方式の射程**:

| 食い違い | 吸収できるか | 実測 (合成データ、vision 2 s 欠落の最悪誤差) |
|---|---|---|
| 車輪半径が 6% 違う | **できる** | 217 mm → **49.7 mm**、`k_v` が 0.948 へ収束 (真値 0.943) |
| モーメントアームが違う | できる (`k_w`) | — |
| **輪ごとに取付角が違う (CAD 対 同定値)** | **できない** | 311 mm のまま。`k_v` は 0.99 にしか動かない |

> **これは重要な訂正である。** CAD の幾何 (±60/±135) と有効値 (55.4/136.1/−136.3/−57.4) の差は
> **+4.6 / −1.1 / +1.3 / −2.6 度**で、**符号が揃っていない**。共通の角度補正 1 つでは表せない。
> 最小二乗で当てはめても車輪残差は 1.40 → 1.29 rad/s にしか下がらず
> (輪ごとの角度を自由にすれば厳密に 0 になる)、復元される body 速度の誤差も
> 0.035 m/s・0.31 rad/s → 0.034 m/s・0.24 rad/s とほとんど変わらない。
>
> **したがって「幾何から有効値へのずれ」はオンライン較正では埋まらない。**
> 有効値はオフラインで測る (§2.5 の掃引、`loc_ident`、§2.4 の車輪だけの当てはめ)。
> オンライン較正が受け持つのは、**電池・温度・摩耗で動く倍率**のほうである。

- **初期値**: `k_v = k_w = 1`, `k_a = 0`。可動域は倍率 `1 ± 0.25`、角度 `±10°` でクランプする。
- **プロセス雑音**: ランダムウォーク。時定数は分オーダー (電池電圧・温度・摩耗) なので小さく置く。
- **収束値はログに出す。** `k_v` が 1 から大きく離れたままなら、公称の車輪半径が間違っている。

### 4.2 スリップ: R をスリップ量で適応させる (座標系は据え置き)

- **車輪の R をスリップ量で膨らませる**: `R_wheel ← R_wheel · min(exp(‖s‖/s_ref), c_max)`。
  既定 `s_ref = 0.1 m/s`, `c_max = 10`。Yu らが軸ごとに効かせて 1 軸だけ悪化させ、
  著者自身が「適応のさせ方が不適切」と認めているので、**等方**に効かせて上限でクランプする。
- **`α = 1/τ_s > 0` を Validate で強制する。** Yu らの可観測性解析により、
  スリップが可観測なのは `α > 0` のときだけで、`α = 0` (ランダムウォーク) では不可観測になる。
  コメントに根拠を残した。
- **スリップの座標系はロボット系のまま据え置いた。** Yu らは世界座標へ置いて群アフィン性を
  保っているが、それは「氷の上を慣性で滑る」差動駆動の描像に基づく。オムニ車輪の滑りは
  ローラの自由転がりと牽引限界から来るので、機体系のほうが物理的に自然な可能性がある。
  **どちらが良いかは実機のログで比べられる**ので、根拠なく変えない
  (「効果を測れない設定を既定にしない」というこのリポジトリの約束に従う)。

### 4.3 vision の遅延は「相互相関で測る」— 状態にはしない

当初は Qin & Shen に倣って `τ_v` をフィルタの状態にする設計にしていたが、**実装しながら考え直した**。

- 車輪という独立した速度源があるので、**車輪の速度と vision の速度の相互相関**で
  直接測れる (Mair の相互相関法、Kelly & Sukhatme の回転曲線の位置合わせと同じ原理)。
  PoC が実際にこの方法で測っている。
- 状態にすると `v ≈ 0` で不可観測、`v` 一定で位置バイアスと縮退するのでゲートが要る。
  そのゲートの中身は結局「加減速があるか」であり、相関法が自然に持っている性質と同じ。
- 時定数が姿勢推定と 4〜5 桁違う。計画 §5.3 が時計推定をフィルタから分離したのと同じ理由で、
  同じ状態ベクトルに混ぜる利点がない。

**実装** (`internal/localization/visiondelay.go`): 車輪から復元した body 速度の大きさと、
vision の位置差分から作った速度の大きさを同じ時間格子に並べ、正規化相互相関のピーク位置を
放物線補間で求める。速度の**大きさ**を使うので座標系・スケール・向きの誤差に影響されない。

- **合成データでの実測: 真値 0 / 10 / 25 / −15 ms に対し、推定誤差は ±1 ms。**
- 静止・定速では相関の山が立たず、`ok = false` を返す (不可観測性がそのまま出る)。
- **格子へ載せるときは四捨五入すること。** 切り捨てにすると、車輪 (格子にちょうど乗る) に
  対して vision だけが平均 4 ms 早くずれ、それがそのまま推定値の偏りになる (実装中に踏んだ)。

指令が効くまでの遅れ (§4.4) も同じ仕掛けで測る。

### 4.4 `PredictAhead` — 制御が使える出力にする

`Estimate` を「今」ではなく「指令が効く時刻」で返せるようにする。

- `PredictAhead(τ)` は公称状態を `τ` だけ進め、共分散も `F P Fᵀ + Q(τ)` で進める。
  **ホライズンに上限** (既定 150 ms) を課し、超えたら打ち切って `Health = DEGRADED`。
- **`τ` は固定値にできない。** PoC は「指令が効くまでの遅れは電池の電圧で変わる」
  (午前 21〜23 V で 85 ms が最適、満充電 24 V では効きすぎて 18〜20 mm 先走った) と実測している。
  → **推定器が `τ_act` をオンラインで推定する**: 指令速度と推定速度の相互相関を
  スライディング窓で取り、遅れのピーク位置を出す。制御側はそれを読んで先読み量に使う。
  これは推定の状態には入れない (時定数が違う・制御の都合なので) が、同じパッケージから提供する。

### 4.5 ZUPT / ZARU — 実測が「効く」と言っている

PoC の実測が停止判定の材料をくれた。

- **このテスト機は 20 mm/s 以下の指令ではほぼ動かない** (静止摩擦)。
- 停止後、**指令 0 のまま 0.12〜0.17 s で 11〜12 mm 流れる** (指令の遅れ)。
- **止まった後も向きが ±5° で振動する** (位置 P と向き P の相互作用)。

判定は **3 条件の AND**: (1) 4 輪速がすべて閾値以下、(2) 直近 100 ms の vision の位置変化が閾値以下、
(3) §2.4 の冗長残差が正常。満たしたら `v = 0`, `ω = 0` を非常に小さい R で入れる。
**継続時間に上限**を設け (誤検出時に位置が固まるのを防ぐ)、解除は 1 条件でも崩れた瞬間。

### 4.6 雑音パラメータを実測値へ置き換える

**合成データに合わせ込まない**という約束は守る。**入れるのは実機の実測値**である。

| パラメータ | 現在 | 新しい既定 | 根拠 |
|---|---|---|---|
| `VisionPosNoise` | 5 mm | **0.4 mm** | PoC §5-11 の実測 (0.2〜0.4 mm RMS) |
| `VisionAngNoise` | 0.5° | **0.32°** | 同上 (0.25〜0.32°) |
| `WheelNoise` | 0.01 rad/s (定数) | **σ0 = 0.02 + k·|ω|, k = 0.02** | PoC §5-17 (0.3 rad/s が妥当) + §3.7 |
| `SlipTau` / `SlipNoise` | 0.1 s / 1.0 | 据え置き | 合成データの掃引だが、文献の裏づけがある (§3.3) |

> **注意**: PoC の vision 雑音は「150 ms 窓の 2 次式当てはめの残差」なので、**短期の再現性**であって
> 絶対精度ではない。カメラ較正の偏りやフィールド位置依存の系統誤差はここに入らない。
> フィルタの平滑化にとっては短期雑音が正しい量だが、**絶対精度は別に測る必要がある** (§6)。
> VB 適応 R (§3.6) を入れるのは、この既定値を間違えたときの保険でもある。

### 4.7 IMU が載ったときの姿 (今から枠だけ作る)

`FW/MainBoard_V26_2` ブランチに LSM6DSO32 を読む実装 (`lsm6dso32.h`, `imu_test.c`) がある。
載った時点で:

- **ジャイロは予測の入力** (`ω̂ = z_gyro − b_ω`)。`ω` を状態から落とし、`b_ω` を足す。
  これが計画 §4.2 の本来の姿で、RAVEN 側の調査文書の結論とも一致する。
- **加速度計は予測に入れない** (§3.1 の RTT の実測)。**衝突検出のみ** — 閾値を超えたら数十 ms だけ Q を膨らませる。
- **ZARU** (`ω = 0` の疑似観測) で停止のたびにバイアスを較正し直す。
- 必要なデータ形式は §6.2 に書いた。

> **注意: ジャイロバイアス `b_g` と回転の倍率 `k_w` は、ヨーレートが一定だと完全に縮退する**
> (`b_g ≈ (k_w − 1)·ω`)。分離するのは **(a) ω が変化する走り、(b) 停止 (ZARU)** のどちらか。
> 実装後の合成データで確認済み: 一定 3 rad/s で回し続けると バイアス推定が 0.0079 rad/s
> (真値 0.020) までしか寄らず、向きの誤差が 0.97° → 1.94° と**悪化**した。
> ヨーレートが変化する軌道に変えると 0.0207 rad/s まで当たり、1.20° → 0.41° に改善した。
> **試合中は停止が頻繁にあるので実害は小さいが、較正走行を設計するときは必ず ω を振ること。**

### 5.2 実機データで見つかった不具合

1. **車輪サンプルを黙って捨てていた。** vision の観測時刻が車輪より先になると
   (`VisionDelayComp` が負、または車輪の刻印が遅れている) `dt < 0` で棄却していた。
   実機ログでは **710 周期中 0 回しか車輪更新が入っていなかった**のに、vision だけで
   それらしく動いてしまっていた。OOSM の巻き戻し経路へ通すよう直し、回帰テストを固定した。
2. **ZUPT のしきい値が雑音より低かった。** 車輪 0.15 rad/s は実測の静止時雑音 0.23 rad/s
   より小さく、**一度も成立しなかった**。0.7 rad/s (3 シグマ) に上げ、判定の主役は
   vision の見かけ速度に移した。
3. **相互相関の格子への載せ方が偏っていた。** 切り捨てで載せると vision だけが
   平均 4 ms 早くずれる。四捨五入に直した。
4. **機能比較の基準が設定ごとに変わっていた。** 疑似真値を各設定の平滑化で作ると
   「その設定のオンライン推定が、その設定の平滑化にどれだけ近いか」を測ることになり、
   機能を切ったほうが良く見える嘘の表が出る。基準を 1 度だけ作って固定した。

### 5.3 未達と、その理由

- **一貫性。** 合成データの NEES は 0.69〜0.96 (理想 3.0)、95% 区間に入る割合 73〜83%。
  ほぼすべて弱気側で、過信サンプルは 1126 中 0〜1。計画 §10-8 の「両側 90%」は未達だが、
  §5.0 のバグを直す前 (0.2〜0.3 / 30%) からは大きく改善した。
  残る弱気の出どころはプロセス雑音と `VisionTimeSigma` の保守性。
  **実戦データ (欠落と接触を含む) で詰めること。** 道具は揃っている
  (`loc_replay -qsweep` が NIS の表を出す)。
- **vision の時刻の不確かさを R に足した** (計画 §5.3 の手当て: `R += (v·σ_t)²`)。
  これを入れる前は 3 m/s で過信サンプルが 20/1126 出ていた。既定 σ_t = 2 ms。
- **プロセス雑音は実測ではなく導出値。** 加速度 rms 4 m/s²・相関時間 0.1 s から
  `q = 2a²τ` で 1.8 → 既定 2.0。角も同様に 5.0。
  **以前の 20.0 は大きすぎた**(1 周期で角速度が 1.9 rad/s 変わる想定になり、
  向きの予測の不確かさが vision の雑音を超えていた)。
- **スリップの座標系は変えていない** (§4.2)。
- **IMU は実機に無い**ので、ジャイロ経路の数字はすべて合成データである。
- **疑似真値 (RTS スムーザ) はモデルの仮定をそのまま受け継ぐ。**
  滑りが実際にあるときは欠落区間で明確に勝つ (31.5 → 17.8 mm) が、
  **滑りが無い走りではオンライン推定と並ぶか、わずかに負ける** (2.90 対 3.06 mm)。
  スリップ状態が「使われない自由度」になり、欠落区間の変位を v と s に配分して
  しまうためで、位置は v からしか積まれないので配分を誤ると位置が悪くなる。
  オンライン推定は因果なのでこの自由度を使えず、かえって悪化しない。
  **欠落区間を疑似真値で評価するときは、その走りに滑りがあるかを意識すること。**

## 6. 測ってほしいこと

### 6.1 機械 — もう決着している

- ✅ **`Robot_V2.step` は現行の Rock5A 機体。全機体がこの設計** (2026-09-23 確認)。
- ✅ **幾何は CAD どおり** (±60.0000 / ±135.0000°、接地点半径 78.450 mm、ローラの傾き 0°)。
- ⏳ **有効値は機体ごとに測ること。** 摩耗・ゴムの個体差で変わるので、
  新しい機体・タイヤを替えた機体では測り直す。手順は §2.5 (車輪だけの推測航法の掃引) と
  §2.6 (半径の比は車輪ログだけで出る)。

### 6.2 IMU のデータ形式 (回路担当への依頼)

**欲しい形** — SPI 上りフレームのバイト 12–18 (現在 0 埋め) に:

| オフセット | 型 | 内容 | スケール | 備考 |
|---|---|---|---|---|
| 12–13 | `int16` LE | `gyroZ` | **1 LSB = 1/16.4 dps** (±2000 dps) | **生値**。オフセット除去済み、積分しない |
| 14–15 | `int16` LE | `accelX` | 1 LSB = 1/1024 g (±32 g) | 前方 +。衝突検出用 |
| 16–17 | `int16` LE | `accelY` | 同上 | 左 + |
| 18 | `uint8` | **CRC-8** (多項式 0x07、バイト 0–17) | — | §6.3 の理由で必須 |

**守ってほしい約束**:

1. **積分済みの姿勢角ではなく、生の角速度を送ること。** 積分値だとバイアスが観測できず、
   ジャイロを予測の入力にできない (計画 §12-B2)。
2. **レンジは ±2000 dps。** ファームの `ROBOT_MAX_ANG_VEL` は 10 rad/s = 573 dps で、
   試験ブランチの ±500 dps 設定では**飽和する**。衝突時の瞬間値にも余裕が要る。
   量子化 0.061 dps = 0.001 rad/s は RTT の実測雑音 0.037 rad/s の 3% なので埋もれる。
3. **サンプリングは SPI の 8 ms 周期に同期させ、「いつ読んだか」を固定にすること。**
   周期の何 ms 前に読んだかを教えてもらえれば `timeOffsetMs` に入れる。
   ばらつく場合はその幅を教えてほしい (プロセス雑音に載せる)。
4. **デジタルフィルタ (LPF) の設定値を教えてほしい。** 群遅延の見積もりに要る。
   できれば **ODR 833 Hz / LPF は 100 Hz 以上**にして、機上で必要なら落とす。
5. **符号の向き**: 反時計回りを正、機体前方 +x、左 +y。違うならその旨を。

### 6.3 CRC を 1 バイト入れてほしい (再掲・重要度が上がった)

現在フレーム同期はヘッダ 0xFF + フッタ 0xAA + **パディング 7 バイトの 0** で判別しており、
一致を要求できるのは 9 バイトぶんある。**IMU を 12–18 に載せると 3 バイトへ落ち**、
8 ms 周期なら数時間に 1 回の割合で偽のフレーム同期を引く。
PoC §5-19 で「STM からの受信が起動直後にずれると、戻らない限りロボットは動かない」事象が既に起きている。
**CRC-8 を 1 バイト入れれば両方まとめて解決する。**

### 6.4 vision の絶対精度

PoC が測ったのは短期の再現性 (0.2〜0.4 mm) であって、**絶対精度ではない**。
フィールドの中央・端・カメラ境界で、既知の位置にロボットを置いて偏りを測ってほしい。
偏りが位置に依存するなら、VB 適応 R では吸収できない (系統誤差なので) 。

---


### 6.5 まだデータが無い条件

`trajpoc-dataset` の 47 本には、**推定器の値打ちが出る条件がひとつも入っていない**。

| 要る条件 | なぜ | 撮り方 |
|---|---|---|
| **vision の欠落** | 推定器の本命。合成では 2 s で 55° → 1.5° | 自機の模様を一時的に隠す、または受信を一定時間落とす |
| **停止を含む走り** | ZUPT の効果と、止まり際のクリープ | 走って止まって 3 秒待つ、を数回 |
| **意図的な滑り** | スリップ状態と冗長残差の検証 | 滑る面の上、または急加減速 |
| **速い走り (1〜3 m/s)** | 既存は 0.2〜0.4 m/s しかない。遅延の効きが速度に比例する | 安全を確保して直線で |
| **ヨーレートを振る走り** | ジャイロが載ったとき `b_g` と `k_w` を分離するのに要る (§4.7) | 旋回速度を連続的に変える |
| **複数のカメラ・フィールド端** | vision の絶対精度の位置依存 | 場所を変えて静止 |
